# Мінімальні ціни

Мінімальна ціна — найменша сума в старкоїнах, за яку предмет (або рідину) можна продати іншим гравцям:
на аукціоні чи в торговому блоці. Вона потрібна, щоб ніхто не обвалював ринок, продаючи речі майже
даром.

Ціни ніхто не вписує вручну: сервер **сам рахує їх з рецептів гри**, починаючи від сирих руд. Що більше
ресурсів і роботи йде на предмет, то дорожчий він.

Код: `common/src/main/java/com/roll_54/roll_mod/economy/minprice/`.

---

## Для гравців

### Де побачити ціну

Наведи на предмет — у підказці буде **«Мін. ціна: N старкоїнів»**. Для стаку видно ціну за штуку і за
весь стак. Для рідин в EMI/JEI — за 1000 mB (одне відро).

### Що буде при продажу

- **Аукціон:** лот не можна виставити дешевше за мінімальну ціну (для ставок — стартову ціну).
- **Торговий блок:** позицію не можна створити з ціною, нижчою за мінімальну.
- Якщо мінімальна ціна згодом **зросла**, а позиція лишилась дешевшою, вона **вимикається**, доки
  власник не підніме ціну.
- Жоден предмет не продається дешевше за **абсолютний мінімум** (за замовчуванням 1 старкоїн за штуку).
- Сума завжди **округлюється вгору**, один раз для всього лоту: 64 предмети по 1,05 = 67,2 → 68.

| Повідомлення | Що означає |
|---|---|
| «…не можна виставити дешевше за N старкоїнів» | Підніми ціну хоча б до N. |
| «Мінімальні ціни ще обчислюються» | Сервер щойно запустився або перераховує ціни. Зачекай трохи. |
| «Ця пропозиція дешевша за мінімальну ціну сервера і вимкнена» | Власник торгового блоку має підняти ціну. |

## Для адміністраторів

### Увімкнути

Конфіг `config/min_price.json5` (редагується і з гри, рівень доступу 4). Головний вимикач — `enabled`.
Після будь-якої зміни з гри ціни перераховуються самі.

### Handset — вибір рецептів, за якими рахується ціна

Єдина команда мінімальних цін (рівень доступу 2, потрібен EMI):

```
/rollmod admin minprice handset
```

Відкриває дерево рецептів. Предмет у руці одразу стає коренем дерева.

1. **Предмет.** Той, що в руці, або перетягни інший зі списку EMI у слот угорі. Коліщатко над слотом
   змінює кількість (із Shift — по 10), ПКМ очищає. Поруч зі слотом — **поле ціни**: сіра підказка в
   ньому — поточна мінімальна ціна предмета на сервері.
   - **Вписати ціну вручну:** введи число (за штуку; для рідини — за відро) і натисни Enter або
     «Зберегти». Ця ціна діє **незалежно від рецептів** (записується в `itemWhitelist` /
     `fluidWhitelist`).
   - **Повернути ціну з рецептів:** впиши `-` і натисни Enter.
2. **Рецепти:**
   - **«Авто»** — сам обирає найпростіший рецепт для кожного інгредієнта, аж до базових ресурсів;
   - **клік** по предмету — відкриває його рецепти в EMI, обери потрібний кнопкою біля рецепта;
   - **Shift+клік** — EMI сам обирає рецепт для цього предмета;
   - **ПКМ** — прибрати рецепт (предмет знову базовий ресурс).
3. **«Зберегти»** — надсилає обрані в дереві рецепти на сервер: для кожного предмета з обраним рецептом
   ціна відтепер рахується **лише за цим рецептом** (записується в `itemRecipes`). Сервер одразу
   перераховує таблицю й розсилає гравцям — **ціни міняються в реальному часі**, ціна біля слота теж.

Внизу дерева — **«Базові ресурси»**: усе, що треба добути. Жовта рамка — рецепт є, але не обраний.
Червона — предмет уже крафтиться вище в дереві. Дерево рухається мишкою, коліщатко над ним змінює
масштаб, **«Скинути»** прибирає всі обрані рецепти.

Не зберігаються: вибір одного предмета з тегу (це не рецепт) і синтетичні сторінки EMI, яких немає
серед рецептів сервера.

### Як виправити ціну

| Проблема | Що зробити |
|---|---|
| Ціна завелика або замала | Handset → обери інший рецепт → «Зберегти». Або додай поганий рецепт у `recipeBlacklist`, або зміни множник його типу. |
| Ціна 1, хоча мала б бути більша | Предмет не має рецептів, які сервер зміг прочитати. Задай ціну в `itemWhitelist`. |
| Предмет не повинен мати ціни | `itemBlacklist` (абсолютний мінімум усе одно діє). |
| Побічний продукт рецепта занадто дорогий | `outputWeights` для нього менше 1. |
| Нова руда | Додай у `oreTiers` (руди з `OreDefinitions` там уже є). |
| Ціна рідини | `fluidWhitelist`: рідина → ціна за відро. |

### Налаштування (`config/min_price.json5`)

| Поле | За замовчуванням | Що робить |
|---|---|---|
| `enabled` | `true` | Головний вимикач. Вимкнено — нічого не рахується й не перевіряється. |
| `blockSalesUntilReady` | `false` | Поки таблиця будується, забороняти продаж. Вимкнено — до готовності діє лише абсолютний мінімум. |
| `allowFreePositions` | `false` | Дозволити позиції торгового блоку з ціною 0 (роздачі). |
| `absoluteMinPrice` | `1` | Найнижча ціна одного предмета (і одного відра рідини) при продажу. |
| `itemRecipes` | порожньо | Предмет → рецепт, за яким рахувати ціну. Заповнюється кнопкою «Зберегти» в handset; можна й вручну. |
| `tiers` | overworld 100 … glacio 5000 | Ціна одного шматка сирої руди за рівнем (виміром). |
| `oreTiers` | усі руди | Сира руда (id або `#тег`) → рівень з `tiers`. Руда з кількох вимірів бере найдешевший. |
| `itemWhitelist` | порожньо | Предмет (id або `#тег`) → фіксована ціна, не рахується з рецептів. |
| `fluidWhitelist` | вода 0, лава 5 | Рідина → фіксована ціна за відро. |
| `itemBlacklist` | порожньо | Предмети без розрахованої ціни (пріоритет над whitelist). |
| `recipeBlacklist` | порожньо | Рецепти, які не враховуються. `*` у кінці — префікс: `kubejs:*`. |
| `recipeTypeMultipliers` | ваніль, MI | Тип рецепта → множник вартості (робота, енергія). |
| `defaultTypeMultiplier` | `1.0` | Множник для типів, яких немає вище. |
| `skipUnknownTypes` | `false` | Ігнорувати рецепти невідомих типів замість множника за замовчуванням. |
| `outputWeights` | порожньо | Предмет → частка вартості рецепта на одиницю, коли рецепт дає кілька продуктів. |

Приклад `itemRecipes` вручну (ключ — id предмета, `#тег` або `fluid:<id>`; значення — id рецепта):

```json5
itemRecipes: {
  "minecraft:iron_ingot": "minecraft:iron_ingot_from_smelting_raw_iron",
  "#c:ingots/copper": "minecraft:copper_ingot_from_smelting_raw_copper",
  "fluid:modern_industrialization:steam": "modern_industrialization:boiler/steam"
}
```

Рядки з невідомими id/тегами/рецептами не ламають розрахунок — вони пишуться в лог як `[MinPrice] ...`.

### Право LuckPerms

`rollmod.minprice.bypass` знімає всі перевірки мінімальної ціни (див. `docs/luckperms-keys.txt`):

```
/lp group admin permission set rollmod.minprice.bypass true
```

## Як це працює (довідник)

### Розрахунок таблиці

1. **Знімок** (`RecipeSnapshot`, у серверному потоці): рецепти, теги й конфіг переводяться в прості рядки
   й числа; кожен рецепт читає свій адаптер (див. нижче).
2. **Розв'язувач** (`PriceSolver`, у фоновому потоці):
   - фіксовані ціни (руди за рівнями, whitelist, blacklist = 0) записуються першими;
   - предмет, який жоден рецепт не робить, — «лист» (`LEAF`), ціна = абсолютний мінімум;
   - ціна предмета = **найдорожчий** з рецептів, що його роблять, або той, що в `itemRecipes`;
     ціна рецепта = Σ (найдешевший варіант кожного інгредієнта × кількість) − повернуті залишки
     (відро з-під молока тощо), × множник типу, поділена між продуктами за `outputWeights`;
   - ціни в таблиці **точні, дробові й не округлюються**: дешеві проміжні предмети (дошки по 0,26,
     палиці по 0,14) так і входять у наступні рецепти, і множники працюють на кожному кроці.
     Абсолютний мінімум і округлення вгору застосовуються лише при продажу;
   - предмет рахується, лише коли **всі** його рецепти можна порахувати; що чекає саме на себе (цикли
     злиток ⇄ блок) — розрізається за рецептами, які вже можна порахувати (`CYCLE`); цикл, у який
     ззовні нічого не веде, — `UNRESOLVED` (ціна = абсолютний мінімум);
   - ціна, раз записана, не змінюється — тому цикли не роздувають її до нескінченності.
3. Готова таблиця підміняє стару цілком (стара працює, поки будується нова) і розсилається гравцям.

Перебудова: на старті сервера, після `/reload`, після зміни конфігу з гри і після «Зберегти» в handset.

**Рідини** мають ціну за відро (ключ `fluid:<id>`). **Тара з рідиною** (наповнене відро, бак MI, будь-який предмет з рідиною) = ціна самої тари (для
відра — порожнього відра) + ціна рідини в ній за кількістю відер. **Контейнери** (шалкери, мішечки) коштують себе плюс усе, що в них лежить (до 4 рівнів).

### Які рецепти розуміються

| Тип | Як читається |
|---|---|
| Будь-який рецепт з `getIngredients()` + `getResultItem()` (верстак, печі, каменеріз, багаття, AE2 Charger і трансформація, більшість модів) | кожен непорожній слот = 1 інгредієнт; залишки в сітці віднімаються. |
| Modern Industrialization та аддони на його машинах (EI, YAI…) | предмети й рідини з кількостями; шанс входу множить кількість, вхід з шансом 0 (каталізатор) не витрачається; виходи з шансом < 1 не враховуються. |
| MI Forge Hammer | вхід з кількістю. |
| Ковальський стіл (smithing transform) | шаблон + основа + додаток. |
| **MBD2** (машини roll_mod) | предмети й рідини з рецепта; per-tick входи × тривалість; шанс 0 — каталізатор; виходи з шансом < 1 не враховуються. Енергія не враховується. |
| **AE2 Inscriber** | у режимі INSCRIBE преси не витрачаються, у режимі PRESS — витрачаються. |
| **Farmer's Delight, обробна дошка** | ніж не витрачається; лише гарантовані результати. |
| **Farmer's Delight, казан** | інгредієнти + тарілка/пляшка, в яку подається страва. |

Не рахуються: рецепти без видимого результату чи інгредієнтів (копіювання карт, феєрверки,
фарбування), рецепти з порожнім тегом і все з `recipeBlacklist`. Скільки рецептів кожного типу
прочитано й пропущено — у лозі після збірки (`[MinPrice] adapted: {...}` / `skipped: {...}`).

### Де перевіряється

| Місце | Коли | Обхід правом |
|---|---|---|
| Аукціон (`AuctionManager`) | виставлення лоту | так |
| Торговий блок, нова позиція (`AddPositionPacket`) | створення/зміна позиції | так |
| Торговий блок, угода (`VendorBlockTransaction`) | кожна покупка: позиція, що опинилась дешевшою за підняту мінімалку, вимикається | ні |

### Клієнт

Сервер надсилає `SyncMinPricesPacket` (предмет → ціна за штуку, рідина → ціна за відро, абсолютний
мінімум) при вході і після кожної перебудови. Підказки: «Мін. ціна: N старкоїнів» (для стаку — за штуку
і разом), для рідин у JEI/EMI — за 1000 mB; на тарі з рідиною — сума і під нею «(тара X + рідина Y)». При виході з сервера
клієнтська копія очищається. «Зберегти» і Enter у полі ціни в handset — `SaveMinPriceRecipesPacket` (рецепти й вписані ціни; лише
для рівня доступу 2; рецепти, яких сервер не знає, відкидаються).
