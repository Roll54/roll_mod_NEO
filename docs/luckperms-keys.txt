================================================================================
 roll_mod - LuckPerms keys
================================================================================

Everything the mod reads out of LuckPerms, in one place. Generated by hand from
the source; the single class that touches the LuckPerms API is

    common/src/main/java/com/roll_54/roll_mod/economy/vendingblock/auction/LuckPermsCompat.java

with two exceptions noted at the bottom (RankResolver, PrimeManager).

Rule this mod follows (see LUCKPERMS_VALUE_PERMISSIONS.md):
  - a NUMBER goes in META            /lp group <g> meta set <key> <value>
  - a YES/NO goes in a PERMISSION    /lp group <g> permission set <node> true

Without LuckPerms installed, every permission below reads as false and every
meta as unset, and the mod falls back to the defaults given here.


================================================================================
 1. META  (value-bearing; always an integer)
================================================================================

--------------------------------------------------------------------------------
 rollmod.warps.max                                                    (a count)
--------------------------------------------------------------------------------
  How many warps the player may keep.
  Unset:      3 with rollmod.ah.prime, otherwise 1
  Read by:    WarpService.limitFor
  Example:    /lp group vip meta set rollmod.warps.max 5

--------------------------------------------------------------------------------
 rollmod.homes.max                                                    (a count)
--------------------------------------------------------------------------------
  How many homes the player may keep.
  Unset:      8 with rollmod.ah.prime, otherwise 3
  Read by:    HomeService.limitFor
  Example:    /lp group vip meta set rollmod.homes.max 10

--------------------------------------------------------------------------------
 rollmod.ah.positions                                                 (a count)
--------------------------------------------------------------------------------
  How many auction listings the player may have active at once.
  Unset:      config "ahMaxListings" (default 5)
  Read by:    LuckPermsCompat.maxListings -> AuctionManager
  Example:    /lp group vip meta set rollmod.ah.positions 15

--------------------------------------------------------------------------------
 rollmod.rtp.cooldown                                                   (TICKS)
--------------------------------------------------------------------------------
  Wait between random teleports for this rank. Waived entirely by
  rollmod.rtp.bypasscooldown.
  Unset:      config roll_mod.json5 -> rtp.cooldownTicks (default 12000)
  Read by:    RtpService.cooldownRemainingMillis
  Example:    /lp group vip meta set rollmod.rtp.cooldown 2400        (2 min)

  THERE IS NO KIT COOLDOWN META, and that is deliberate - see the note under
  rollmod.kit.<name> in section 2.

  NOTE ON UNITS: every DURATION in this mod is ticks (20 ticks = 1 second;
  12000 = 10 minutes; 1728000 = 24 hours). That is also the unit
  /kit create <name> <cooldownTicks> takes and the unit the kit files store, so
  there is one number to think about. Only the timestamps written to
  minestar/ are milliseconds, and nobody sets those by hand.

  A meta value that is not a whole number, or is negative, is ignored and the
  fallback applies. The value is read fresh on every check, so a change takes
  effect at once - no relog.


--------------------------------------------------------------------------------
 rollmod.heal.cooldown                                                  (TICKS)
--------------------------------------------------------------------------------
  Wait between /heal uses for this rank. Waived entirely by
  rollmod.heal.bypasscooldown.
  Unset:      config roll_mod.json5 -> heal.cooldownTicks (default 12000)
  Read by:    HealService.cooldownRemainingMillis
  Example:    /lp group vip meta set rollmod.heal.cooldown 2400        (2 min)


================================================================================
 2. PERMISSIONS  (plain yes/no nodes)
================================================================================

--------------------------------------------------------------------------------
 rollmod.ah.prime
--------------------------------------------------------------------------------
  The mod's one "premium rank" flag. Three things hang off it:
    - auction listings may run for config "ahPrimeDays" days (default 30)
      instead of "ahMaxDays" (default 10)
    - the larger warp allowance (3 instead of 1) when rollmod.warps.max is unset
    - the larger home allowance (8 instead of 3) when rollmod.homes.max is unset
  Read by:    LuckPermsCompat.isPrime / maxDurationDays

  Separate from the LuckPerms group named "prime" that PrimeManager grants - see
  section 4.

--------------------------------------------------------------------------------
 rollmod.warps.moderate
--------------------------------------------------------------------------------
  Receives warp reports and may approve or block a warp without being an
  operator. This is what "moderation and higher" means on this server.
  Read by:    LuckPermsCompat.canModerateWarps

--------------------------------------------------------------------------------
 rollmod.warps.bypasswarmup
--------------------------------------------------------------------------------
  Warps travel at once for this player, with no 3-second countdown - the same
  way official warps do for everyone.
  Read by:    WarpService.begin

--------------------------------------------------------------------------------
 rollmod.kit.<name>
--------------------------------------------------------------------------------
  May claim that kit. One node per kit, named after the file:
  minestar/kits/starter.json -> rollmod.kit.starter

  A kit the player has no node for is not merely refused: it is not sent to
  their client at all, so it does not appear in the F4 screen or in /kit's
  tab-completion.

  A kit file may name a different node in its "permission" field; blank means
  the default above.

  Without LuckPerms installed this would hide every kit, so operators (level 2)
  get all of them - a single-player world is no place to enforce ranks.
  Read by:    LuckPermsCompat.canUseKit -> KitService.canUse
  Example:    /lp group vip permission set rollmod.kit.vip true

  THE ACCESS NODE IS THE ONLY KIT KEY. A kit's COOLDOWN cannot be shortened,
  waived or bypassed by anything: no permission, no meta, no rank, and not by
  being an operator. It comes from "cooldownTicks" in the kit file and from
  nowhere else.

  So give a rank a faster kit by giving it a DIFFERENT KIT:

      minestar/kits/starter.json      cooldownTicks 72000   rollmod.kit.starter
      minestar/kits/starter_vip.json  cooldownTicks 12000   rollmod.kit.starter_vip

  which also keeps what each rank actually receives visible in the files rather
  than spread across LuckPerms.

--------------------------------------------------------------------------------
 rollmod.rtp.bypasscooldown
--------------------------------------------------------------------------------
  No wait between random teleports for this player. Random teleports only -
  there is no equivalent for kits, on purpose (see above). To shorten the /rtp
  wait rather than remove it, use the rollmod.rtp.cooldown meta instead.
  Read by:    LuckPermsCompat.canBypassRtpCooldown

--------------------------------------------------------------------------------
 rollmod.fly.use
--------------------------------------------------------------------------------
  May use /fly. The toggle is remembered in the player's own data, so it
  survives a logout, a death and a portal; take the node away and their flight
  ends at their next login, but the toggle stays set, so giving the rank back
  gives the flight back too.

  Dimensions where /fly is refused are config, not LuckPerms: roll_mod.json5 ->
  fly.blacklistedDimensions. There is nothing to bypass them with, on purpose.
  Read by:    LuckPermsCompat.canFly

--------------------------------------------------------------------------------
 rollmod.heal.use
--------------------------------------------------------------------------------
  May use /heal: full health, a full stomach, no fire and no harmful effects.
  The wait between uses is rollmod.heal.cooldown (section 1).
  Read by:    LuckPermsCompat.canHeal

--------------------------------------------------------------------------------
 rollmod.heal.bypasscooldown
--------------------------------------------------------------------------------
  No wait between heals for this player. It grants nothing on its own - a rank
  still needs rollmod.heal.use to heal at all. To shorten the wait rather than
  remove it, use the rollmod.heal.cooldown meta instead.

  LuckPerms nodes do not nest: rollmod.heal.use and rollmod.heal.bypasscooldown
  are two separate grants (though the wildcard rollmod.heal.* is both).
  Read by:    LuckPermsCompat.canBypassHealCooldown


================================================================================
 3. QUICK REFERENCE
================================================================================

 META (numbers)
   rollmod.warps.max          count    warps allowed         3 prime / 1
   rollmod.homes.max          count    homes allowed         8 prime / 3
   rollmod.ah.positions       count    active listings       config, 5
   rollmod.rtp.cooldown       ticks    /rtp wait             config, 12000
   rollmod.heal.cooldown      ticks    /heal wait            config, 12000

   (no kit cooldown meta exists - a kit's wait is the kit file's, always)

 PERMISSIONS (true/false)
   rollmod.ah.prime                    premium rank flag
   rollmod.warps.moderate              may act on warp reports
   rollmod.warps.bypasswarmup          warps are instant
   rollmod.kit.<name>                  may claim that kit
   rollmod.rtp.bypasscooldown          no /rtp wait  (kits: never bypassable)
   rollmod.fly.use                     may use /fly
   rollmod.heal.use                    may use /heal
   rollmod.heal.bypasscooldown         no /heal wait

 Setting them:
   /lp group vip meta set rollmod.homes.max 10
   /lp group vip permission set rollmod.kit.vip true
   /lp user <player> meta set rollmod.rtp.cooldown 600
   /lp user <player> meta unset rollmod.rtp.cooldown
   /lp group vip meta info


================================================================================
 4. LUCKPERMS THINGS THAT ARE NOT KEYS
================================================================================

Two features read LuckPerms without naming a node or a meta key.

 GROUPS AND WEIGHT - RankResolver
   The rank shown in the F4 screen is the player's highest-WEIGHTED inherited
   group; with none, "player". So group weight is what decides which rank a
   player is displayed as, and no configuration here is needed for a new group
   to show up.

   A group is given a pretty name through the lang key  rank.roll_mod.<group>
   (e.g. rank.roll_mod.helper). Without that key the raw group id is shown, so
   a new group needs no code change.

   The group named "helper" is the staff floor: anything weighted at or above it
   counts as staff, which is what StaffCommandLogger records.

 THE "prime" GROUP - PrimeManager (server module)
   A LuckPerms group literally named "prime", granted and revoked by the server
   module's own logic. This is a group, not the rollmod.ah.prime permission -
   the two are related only by intent, so a rank meant to be premium usually
   wants both.

 NOT LUCKPERMS AT ALL
   Operator rights are not a LuckPerms matter here: they live in
   minestar/operators.json (see docs/minestar-files.md). Commands gated with
   "requires(hasPermission(2))" use vanilla operator level, not a node.
